# Languages guide

## Add a language

1. Pin the version of the language, its package manager and each framework and database that the code in the language uses, such as Python in `.python-version`. Commit the lockfile for the language's packages, and add steps to `.github/workflows/ci.yml` that install those versions and the packages.
2. If the pinned stable package manager has a native release-age control, configure it to reject versions less than 7 days old when resolving new or updated dependencies, including the transitive dependencies it covers. Leave the list of packages exempt from the release-age control empty. Check the selected version's official documentation for its coverage, timestamp precision and cutoff behavior. Keep checking release dates yourself where the control cannot check them, as [Pin versions](dependencies.md#pin-versions) describes.
3. If the package manager has a frozen or locked install mode that rejects a missing or out-of-date lockfile without rewriting it, use that mode in CI. Release-age checks and locked installation are separate safeguards. Whether installation rechecks the ages of existing lockfile entries depends on the manager and version. Configure the two safeguards independently. Without a native release-age control, check release dates yourself. Without a suitable locked install mode, keep the version-pinning and CI setup in step 1.
4. Add the formatter, the linter, the type checker if the language has one, and the tests to `scripts/check`.
5. Add a hook to `.claude/settings.json` and `.codex/hooks.json` that runs the formatter on each file in the language that the agent edits.
6. If the language's coverage tool can mark single lines as excluded, add a coverage check to `scripts/check`. The check fails when a line never runs in a test. Where the tool measures branches, the check also fails when a branch is never taken. Lines marked as excluded don't count, but the check fails on an exclusion marker that gives no reason. Measure coverage with the tests that `scripts/check` runs, and with no others. If the tool can't mark lines as excluded, add no coverage check.
7. If the project publishes a library in the language, and the language has a tool that finds breaking changes, such as cargo-semver-checks for Rust, add a check to CI that looks for a break in the library's public interface. If a pull request breaks the interface, the check fails, unless the pull request's title marks the change with `!` before the colon, as in `feat!: rename the import command`. Have the check compare the pull request with the commit on main that it branched from, not with the last release. Once a breaking change has merged, main itself differs from the last release, so a comparison with that release would fail every later pull request.
8. Add the language's package manager, such as pip or npm, to `.github/dependabot.yml`, so that Dependabot updates its packages too.
9. Update the "Commands" section in `AGENTS.md` with the language's install, run and test commands.
